# 3D 台球瞄准练习（Three.js）

## Problem Statement

用户想练习台球瞄准，但平面示意图难以建立“目标球要进袋，母球到底该撞哪里”的空间感。需要一个打开浏览器就能用的中文单页应用：一键生成合法局面，自动指出最容易进的袋口，并用 3D 画面把进球线、ghost 球、瞄准线、瞄准点和接触点画清楚，同时可以用鼠标旋转、缩放观察。

## Solution

Vite + Three.js 单页应用。随机摆球只生成“母球能把目标球打进至少一个袋口”的局面；按最小切角自动选袋并高亮；在标准尺寸的 3D 球桌上显示母球、目标球、进球线、半透明 ghost 球、瞄准线、瞄准点与接触点；一个按钮只切换进球线和瞄准线的显隐；OrbitControls 提供固定最佳初始视角并支持拖拽旋转/滚轮缩放。所有贴图程序化生成，不使用外部素材；几何判定抽为不依赖 three 的纯函数并用 node:test 锁定。

## Decisions

以下为已经确认的目标与决策，不再重复采访。

1. 单位与尺寸：米；有效台面 2.54 × 1.27；球半径 0.028575；台面 y=0，球心高度 y=R；x 为长轴，z 为短轴。
2. 袋口 6 个：四个角袋位于 `(±W/2, ±H/2)`，两个中袋位于 `(0, ±H/2)`。袋口数组顺序固定，并作为切角平局时的裁决顺序。
3. ghost 球：设目标球 T、袋口 P、单位向量 `u = unit(T − P)`，则 ghost 球心 `G = T + 2R·u`，接触点 `K = T + R·u`。进球线为 T→P，瞄准线为母球心 C→G。
4. 切角：C→G 与 T→P 的夹角，直球为 0°；可行切角范围为 `[0°, 80°)`。
5. 合法性（全部满足才可行）：
   - 目标球、母球、ghost 球心都在有效台面内（各轴向 `±(尺寸/2 − R)`，容差 1e-9），且到任一袋心距离 `≥ 袋口 mouthRadius + R`（整颗球都在袋洞外；容差 1e-9）；
   - `|C − T| > 2R`（两球不重叠）；
   - `|C − G| ≥ 0.15`（瞄准线有可读长度，且母球有击球空间）；
   - 母球不挡进球线：C 到线段 T→P 的距离 `> 2R`；
   - 目标球不挡母球→ghost：T 到线段 C→G 的距离 `≥ 2R − 1e-9`（端点处两球相切合法）；
   - 切角 `< 80°`。
6. 选袋：枚举 6 个袋口，取可行且切角最小者；切角差在 1e-9 内视为相等，按袋口数组顺序取先者。
7. 随机摆球：在有效台面内缩 0.035 的区域内采样目标球与母球，并要求两球中心距 `≥ 0.22`；用 `createShot` 校验，重采样直到有可行袋口；最多 500 次，失败显式抛错，不静默返回非法局面。随机源可注入以便测试。
8. 观察：固定初始相机位于长边斜上方看向台心；OrbitControls 开阻尼，只允许旋转和缩放，禁用平移，限制极角与距离，避免穿地或丢失球桌。
9. 视觉：木框、绿呢、立体库边、六个带金属圈的深色袋口；程序化 canvas 布纹/木纹/球面贴图；目标球用 9 号黄条纹图案，母球为白球带少量红点；MeshPhysicalMaterial + RoomEnvironment 反射、方向光阴影、ACES 色调映射。不使用占位方块或纯色平面。
10. 交互：页面加载即生成一局；按钮“随机摆球”重新生成；按钮在“隐藏进球线和瞄准线”与“显示进球线和瞄准线”之间切换。该按钮只控制两条线，ghost 球、瞄准点、接触点、袋口高亮始终可见；显隐状态跨局面保持；默认显示。
11. 不添加物理、击球、计分、多人、拖球、存档等未要求能力。

## User Stories

1. 作为台球练习者，我想打开网页就看到完整、真实的 3D 球桌，这样无需安装额外软件就能开始练习。
2. 作为练习者，我想点击“随机摆球”得到一局母球与目标球，这样不必手动摆球。
3. 作为练习者，我想随机局面一定存在可进球袋，这样不会面对无解局面。
4. 作为练习者，我想应用自动选中切角最小的袋口并高亮，这样知道该瞄哪里。
5. 作为练习者，我想看到目标球到袋口的进球线，这样理解目标球的运动方向。
6. 作为练习者，我想看到目标球后方的半透明 ghost 球，这样理解母球需要到达的位置。
7. 作为练习者，我想看到母球到 ghost 中心的瞄准线，这样知道母球杆方向。
8. 作为练习者，我想看到 ghost 球心对应的瞄准点，这样在台面上定位。
9. 作为练习者，我想看到目标球上的接触点，这样理解两球接触位置。
10. 作为练习者，我想用鼠标拖拽旋转视角，这样从不同方向检查几何关系。
11. 作为练习者，我想滚轮缩放，这样看清接触点与瞄准点细节。
12. 作为练习者，我想一键隐藏进球线和瞄准线而保留 ghost 球和标记，这样可以专注练习而不被辅助线干扰。
13. 作为练习者，我想再次点击恢复两条线，这样随时切换提示。
14. 作为练习者，我想隐藏状态在重新摆球后保持，这样不会每局都被线打扰。
15. 作为练习者，我想球面有编号/条纹和高光，这样画面可信、球也容易辨认。
16. 作为练习者，我想看到阴影与布面质感，这样空间位置更容易判断。
17. 作为初学者，我想界面和说明是中文，这样无需翻译。
18. 作为开发者，我想安装、开发、构建命令写进 README，这样能复现运行。
19. 作为开发者，我想几何逻辑是不依赖 three 的纯函数，这样用 Node 内置测试即可验证。
20. 作为开发者，我想测试覆盖 ghost 位置、接触点、合法性、最小切角选袋和随机局面不变量，这样改动不会悄悄破坏几何。
21. 作为开发者，我想 `pnpm build` 能生成可部署静态产物，这样上线简单。

## Implementation Decisions

- 单一网页应用，不引入路由、状态库或 CSS 框架。
- 纯几何模块：导出固定台面/球半径常量、6 个袋口规格、`evaluatePocket(cue, target, pocket)`、`createShot(cue, target)`、`randomShot(rng?)`。
  - `evaluatePocket` 返回 `{feasible, ghost, contact, cutAngle}`，不抛异常处理普通非法输入；
  - `createShot` 在可行袋中取最小切角，无可行袋返回 `null`；
  - `randomShot` 返回完整局面 `{cue, target, pocket, ghost, contact, cutAngle}`；
  - 位置用 `{x, z}`，角度用弧度；模块不 import three。
- 渲染层按职责分模块：程序化纹理、球桌与球体、瞄准叠加层、应用装配。渲染层只消费几何结果，不重复判定逻辑。
- 瞄准叠加层：两条线用细管状几何并抬离布面避免 z-fighting；ghost 球为半透明 PBR 球；瞄准点为 ghost 球心正下方布面上的环形标记；接触点为目标球表面的小球标记；袋口高亮为套在袋口的发光环。只有两条线受开关控制。
- 球与桌：标准比例；目标球 9 号黄条纹贴图（白色圆底 + 数字，纹理朝向初始视角）；母球白色带少量红点；布纹与木纹用 canvas 噪声/条纹；环境反射用 three 自带 RoomEnvironment + PMREM，不引入 HDR 文件。
- 相机/渲染：固定初始视角、ACES 色调映射、sRGB 输出、PCFSoft 阴影、像素比上限 2、窗口 resize 自适应、requestAnimationFrame 循环。
- UI：左上角半透明中文面板，标题 + 两个原生 `<button>`，按钮可聚焦；不添加未要求的控制项。
- 不承诺触屏专属布局，但 OrbitControls 默认触控可用。

## Testing Decisions

- 测试只通过纯几何模块的外部行为验证，不测实现细节，不 import three，不启动浏览器。
- 使用 `node:test` + `node:assert/strict`；`pnpm test` 即 `node --test`，在无 node_modules 的 worktree 也可运行。
- 覆盖以下不变量：
  1. 直球局面切角约为 0，且选中对应袋口；
  2. ghost 球心位于 T→P 的反向延长线上，且 `|G − T| = 2R`；
  3. 接触点位于 T 与 G 的连线上，且 `|K − T| = R`；
  4. 母球挡住进球线时该袋不可行；
  5. 母球/ghost 出界、母球到 ghost 的路径穿过目标球时不可行；
  6. 选中袋口的切角等于所有可行袋口切角的最小值；
  7. 随机局面（多个种子）非空、两球不重叠、ghost 与母球在台内、无球挡线、切角在范围内，且选袋最小。
  8. 固定随机序列 `[0.5, 1/1200, 0.5, 0.5]` 首次采样会把母球放到 `(0, -0.599)`（上中袋洞内）；`randomShot` 必须拒绝该次尝试并重采样，返回值中母球、目标球、ghost 到全部 6 个袋心的距离均不小于 `mouthRadius + R`。
- 视觉与交互不写自动化 UI 测试；由任务负责人在集成后的真实浏览器中核对验收 1/2/4。

## Out of Scope

- 台球物理、碰撞、旋转/塞、库边反弹、进袋动画。
- 鼠标瞄准/击球力度、计分、回合、多人。
- 手动拖球/摆球、残局导入、关卡、存档、排行榜。
- 移动端专属布局与触控手势优化。
- 国际化（仅中文）、主题切换、音效。
- 加载外部模型或图片资源。

## Further Notes

- 自动化 checks 只有 `pnpm test`；最终 verify 为 `pnpm install --frozen-lockfile` + `pnpm build`。
- 首次实现需提交 `pnpm-lock.yaml`，并确认 pnpm 10 没有拦截 Vite 构建（build 必须实际通过）。
- 视觉“逼真”的最低标准：程序化贴图 + PBR 反射 + 阴影 + 立体库边与金属袋圈；不得出现占位方块或纯色平面。
- 无 TODO、无“后续优化”项；未使用代码不保留。
