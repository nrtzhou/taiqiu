# 3D 台球视觉修复：真实袋洞与细密台呢

## Problem Statement

用户实测当前 `main`（634419e0）后发现两个视觉问题，功能（随机合法摆球、选袋、瞄准叠加、显隐、拖拽缩放）本身正常：

1. 袋口读成 6 个浮在台面上的圈，而不是洞。布面虽然开了圆孔，但框顶高度上放了亮金色圆环与扁平圆片 collar，默认视角下袋口主要呈现为亮圈，看不到内部暗腔和有深度的袋壁。
2. 台呢像粗糙砂面/编织篮纹。颜色贴图是 512 分辨率下的 4px 条纹方格加逐像素强随机噪声，bump 振幅 22/24、bumpScale 0.15，近距离颗粒感明显，不像细密平滑的台球呢。

## Solution

只改渲染层的袋口构造与台呢材质/程序化纹理：

1. 袋口做成真实袋洞：布面圆孔与木框/库边缺口共同构成开口，开口下方是深色袋桶（可见内壁与袋底，布面以下深度 ≥ 0.10 m），框孔内壁由深色内衬遮挡；围板在袋口处开净空，袋腔全程不被木板封住或露出木板。移除框顶的亮金色圆环与扁平圆片。袋口半径继续取 `POCKETS[].mouthRadius`，几何、选袋、碰撞、瞄准零改动。
2. 台呢改为细密平滑的程序化呢面：颜色贴图提高到 1024，去掉可见的 4px 方格与强随机噪点，使用低对比度细纤维 + 很弱的低频云斑；bump 改为细密低幅噪声，`bumpScale` 0.02–0.04；roughness 保持 0.90–0.94、metalness 0；床面与库边共用同一材质与纹理尺度。

## Decisions

以下决策已确认，不再采访用户。

1. 改动范围仅限球桌渲染（袋口、围板）与程序化纹理及其材质参数；`geometry.js`、瞄准叠加层逻辑、随机摆球、显隐按钮、相机/光照、页面结构不改。现有 `node:test` 语义不变。
2. 袋口尺寸与坐标唯一来源是 `POCKETS`：布面孔半径 = `mouthRadius`；木框缺口沿用现有 `mouthRadius + FRAME_CUT_MARGIN`；围板净空与内衬同坐标对齐。不改任何袋口数值。
3. 袋桶：深色、哑光、双面可见的内衬，从框孔内壁（y≈0.04）延伸到布面以下的袋底（y≈-0.12，即布面以下 ≥0.10 m），底部封闭不透光；内部用光照与粗糙度表现袋壁和袋底，不靠自发光。可用旋转剖面形成整体袋桶，或袋壁 + 独立袋底，但近景不得看到木板、围板或穿透缝隙。
4. 移除所有静态金色 Torus 与框顶扁平 Ring/collar。袋口边缘如需包边，只允许深色、贴合、位于布面高度或略低于布面，且不能读成桌面上独立的一圈。
5. 围板（apron）当前是实心木箱，顶面 y=-0.020，会封住加深后的袋底。围板必须在 6 个 `POCKETS` 坐标处开袋口净空（半径 ≥ `mouthRadius + FRAME_CUT_MARGIN`），其余部分保持连续；袋桶与围板不穿插，任何角度看进袋腔都只见深色内衬。
6. 台呢颜色贴图 1024×1024：基色保持现有绿色调；逐像素细纤维噪声幅度很低（单通道约 ±2–4），叠加很弱的低频云斑（约 ±3–5），生成时保证可平铺；不得出现固定周期的 2px/4px 方格或其他可辨重复图案。
7. 台呢 bump 贴图使用细密低幅灰噪声（无周期条纹），bumpScale 0.02–0.04；不使用 sRGB。roughness 0.90–0.94，metalness 0，保持哑光。
8. 床面与库边继续共用同一个台呢材质；颜色与 bump 贴图的 repeat 保持一致（沿用 2.3），二者 UV 均以米为单位，纹理尺度必须一致。默认视角下不得出现明显重复接缝。
9. 保持 `MeshStandardMaterial`；评估后不引入 sheen，避免高光塑料感，也不增加新依赖。所有纹理继续用 canvas 程序化生成，不引入外部图片。
10. 瞄准 UI 中“当前选中袋口”的青色高亮环属于叠加层，保留且行为不变；它不是袋口构造的一部分。
11. 不添加调试入口、查询参数或临时相机 API；近景截图通过 Playwright 驱动 OrbitControls（滚轮缩放 + 拖拽旋转）完成。

## User Stories

1. 作为练习者，我想看到 6 个有真实深度的袋洞，而不是桌面上的亮圈，这样瞄准袋口时空间感可信。
2. 作为练习者，我想在默认视角就能看出每个袋口是洞，这样不用先旋转视角。
3. 作为练习者，我想靠近观察时看到深色袋壁与袋底，这样袋口有真实的纵深。
4. 作为练习者，我想袋腔内部看不到木板或围板，这样不会出现穿帮的视觉破绽。
5. 作为练习者，我想袋口开口尺寸与瞄准/进球判定一致，这样看到的口径就是可进球的尺寸。
6. 作为练习者，我想台呢显示为细密平滑的绒面，这样球桌看起来像真实台球桌。
7. 作为练习者，我想近距离也看不到粗颗粒、方格或篮纹，这样画面不廉价。
8. 作为练习者，我想床面和库边纹理尺度一致，这样球桌是一个整体。
9. 作为练习者，我想默认视角没有明显重复接缝，这样不会分散注意力。
10. 作为练习者，我想台呢哑光不反塑料高光，这样更像布面。
11. 作为练习者，我想随机摆球、显隐按钮、拖拽缩放照常工作，这样修复视觉不牺牲已有交互。
12. 作为开发者，我想几何与测试语义零改动，这样视觉修复没有回归风险。
13. 作为开发者，我想不新增依赖或外部贴图，这样构建与部署仍然简单。
14. 作为开发者，我想 `pnpm test` 与 `pnpm build` 通过，这样改动可安全集成。

## Implementation Decisions

- 球桌渲染模块：袋口建造从“圆柱井 + 框顶圆片 + 金环”改为“深色内衬袋桶”。袋桶顶部半径略大于木框缺口半径（约 `mouthRadius + 0.010`，嵌进木框以藏住接缝），在布面高度收束到 `mouthRadius`，随后向下收分到袋底；底部封闭。内衬材质为深色（近黑，可带极轻微暖/绿皮革色）、roughness ≥ 0.85、metalness 0、双面渲染、接收阴影；不发光。
- 木框缺口路径保持不变；布面开孔保持不变。两者与袋桶顶部对齐，使框孔内壁被内衬完全遮住。
- 围板从实心 Box 改为带 6 个圆形净空的拉伸形状（或等效的断开/下沉构造），净空半径 = `mouthRadius + FRAME_CUT_MARGIN`（0.009），顶面仍在 y=-0.020，底面仍在 y=-0.14；袋桶底 y≈-0.12 位于围板净空内，不与木板相交。
- 台呢纹理模块：`createClothTexture` 输出 1024×1024 可平铺颜色贴图，算法为低幅度逐像素纤维噪声 + 可循环的低频 value noise 云斑；不画任何周期性条纹。`createClothBumpTexture` 输出细密低幅度灰噪声（可同样叠加弱云斑），保持非 sRGB。
- 球桌材质：台呢 `MeshStandardMaterial`，`bumpScale` 0.03（允许 0.02–0.04），`roughness` 0.92（允许 0.90–0.94），`metalness` 0；颜色与 bump 的 repeat 均为 2.3；床面与库边共用该材质。
- 不引入 `MeshPhysicalMaterial` sheen、不调整相机、灯光、色调映射与叠加层材质。

## Testing Decisions

- 单测 seam 不变：纯几何模块及其 `node:test` 用例是唯一自动化 seam；本次不改其接口、夹具或断言，只要求 `pnpm test` 全绿。视觉构造没有值得锁定的纯函数，不新增实现细节单测。
- 视觉验收 seam：在集成 worktree 启动 Vite（独立端口），用 Playwright headless Chromium、视口 1440×900 截图：
  - 默认视角整桌；
  - 通过滚轮缩放 + 拖拽把相机移近一个角袋与一个中袋，确认袋壁、袋底与袋口纵深；
  - 台呢近距离确认细密平滑、无 4px 方格/粗颗粒/明显接缝。
  - 同次冒烟中点击“随机摆球”若干次、切换显隐按钮、拖拽/缩放，采集 console/page error，必须为 0。
- 截图与 Playwright 脚本只放 `/tmp`，不提交；测试结束后停掉 dev server 与浏览器。
- `pnpm build` 作为票内冒烟；最终 `pnpm install --frozen-lockfile` + `pnpm build` 由协调器在 finish 阶段执行。
